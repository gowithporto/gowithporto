# CHANGELOG

Milestones only — not every commit. Newest at the top.

## 2026-08-12

- **Added: branded offline indicator + global error boundary**: previously, a dropped connection while browsing showed nothing (no visual feedback on stuck client-side navigation) or the browser's own generic native offline page on a full reload, and any uncaught render/fetch error had no custom fallback at all — Next's bare default. Added `src/components/layout/ConnectivityBanner.tsx`, mounted globally in `src/app/layout.tsx`: listens for the browser's `online`/`offline` events for instant feedback, plus polls a lightweight `HEAD /robots.txt` every 20s (paused when the tab isn't visible) to catch the case those events miss — a network interface that stays "up" while the actual internet/site is unreachable. Shows a branded toast (pulsing GoWithPorto mark, navy/gold palette matching the rest of the app) via the existing `react-hot-toast` instance rather than a bespoke fixed-position bar, so it's visually consistent with every other toast in the app for free. Also added `src/app/error.tsx` (branded route-level error boundary, styled to match `not-found.tsx`) and `src/app/global-error.tsx` (minimal self-contained fallback for the rare case the root layout itself throws — no provider/i18n dependency, since those may be what's broken). New i18n keys (`offline.*`, `error.*`) added to `en`/`fr`/`es`. Follow-up fix: the toast's logo icon rendered as a broken-image placeholder when actually tested offline — any icon loaded via URL (whether a `next/image` static import or a plain `public/` file) needs a network request of its own to load, which is exactly what's unavailable while genuinely offline. Fixed by inlining the icon as a base64 data URI (`src/assets/logoMarkDataUri.ts`, generated from `src/assets/Fav Icon.png` via `sharp`) baked into the JS bundle, so it needs zero network access to render.
- **Fixed: `/store-owner` showed the dashboard shell (all-zero stats) instead of redirecting to login after logout**: `src/app/store-owner/layout.tsx` checked for a session only to decide whether to render the sidebar (`showSidebar`) — if there was no session, it fell through to `return <>{children}</>`, rendering the dashboard page anyway instead of redirecting. The page itself (`store-owner/page.tsx`) has no auth guard of its own either, so its data fetches (`/api/store-owner/orders`, `/api/store-owner/connect`) just silently failed/returned empty, producing the "logged out but still see €0.00 everywhere" bug. Fixed by mirroring the existing `/admin` pattern exactly: added `src/components/store-owner/StoreOwnerGuard.tsx` (client-side, `useSession` + redirect unauthenticated → `/store-owner/login`, wrong-role → `/`, mirrors `AdminGuard.tsx`) and converted `store-owner/layout.tsx` to wrap all non-login routes in it, matching `admin/layout.tsx`'s structure.
- **Fixed: email logo sometimes rendering as a broken image in Gmail**: `src/lib/emailTemplates/shared.ts` pointed every transactional email's `<img>` logo at `public/logo.png`, a 3508×2480px, ~193KB print-resolution export displayed at only 180px wide. Gmail proxies/caches external images per-message at first-open time, so any slow fetch of that oversized file could leave that one email's logo permanently broken even though the site itself was fine — explains why it looked random ("sometimes" broken) rather than a real outage. Added `public/logo-email.png` (resized to 540px wide via `sharp`, ~9.6KB — a 20x reduction) and pointed only the email templates at it; left `public/logo.png` untouched since it's also the Open Graph/social-share image (`src/app/layout.tsx`), where the larger size is appropriate. Also excluded the new file from `src/proxy.ts`'s locale-routing matcher, matching the existing exclusions for `logo.png`/`favicon.ico`/etc.
- **Removed the Shipping line from the Cart page**: the cart's own shipping estimate (`src/components/cart/OrderSummary.tsx`) is redundant with — and was previously inconsistent with — the real shipping amount Stripe's payment step already shows, so per founder request it's gone entirely. `OrderSummary` now only shows Subtotal/Total plus a "Shipping calculated at checkout" note; dropped the `FREE_SHIPPING_THRESHOLD`-driven banner too, since that promo logic was tied to the removed cart-side estimate and was never actually enforced at checkout. Deleted the now-unused `GET /api/cart/delivery-fee` route and the cart page's `storeDeliveryFee` state/effect that fed it (both added earlier this same day to fix the estimate — superseded by removing the line instead of fixing its accuracy).
- **Dashboard sidebar cleanup + real Favorites feature**: removed "Premium Member" badge (profile card) and the "Member Tier" stat card from `/dashboard` — no premium/membership tier actually exists yet, both were placeholder UI. Removed "Saved Trips" (redundant with the existing AI History/trip tab) and "Help Center" (already in the footer) from the sidebar's "coming soon" list entirely. "Favorites" is no longer a "coming soon" toast — it's now a fully working feature: added a `Favorite` model (`userEmail` + `itemType` + `itemId`, unique-indexed), `GET`/`POST /api/favorites` (list populated favorites / toggle one) and `GET /api/favorites/check`, plus a reusable `useFavorite(itemType, itemId)` client hook. Wired the heart icon on the shop `ProductCard` and product detail page, the "Add to Favorites" button on attraction and local-experience detail pages, and added a new heart button to bike-rental provider cards (previously had no favorite affordance at all). New `/dashboard/favorites` page lists everything a user has hearted across all four types, with a working unfavorite (heart) button that removes it from the list immediately. Unauthenticated users get a "Log in to save favorites" toast instead of a silent no-op.

## 2026-08-11

- **Fixed: cart page showed a hardcoded €4.90 shipping estimate instead of the store's real delivery fee** — found while testing the new store-edit feature (admin changed M&M Souvenirs' delivery fee to €5, cart still showed €4.90). `src/app/cart/page.tsx` had a `FLAT_SHIPPING = 4.9` constant, completely disconnected from `Store.deliveryFee` — the Stripe checkout itself was always correct since it's built server-side from the real store record, only the cart-page estimate was stale/wrong. Added `GET /api/cart/delivery-fee?productId=` (looks up the cart's first item's store, since a cart only ever holds one store's products — same assumption `/api/payments/checkout` already makes) and wired the cart page to fetch and display the real fee instead of the hardcoded one.

- **Admin can now edit a store's delivery fee and commission rate**: added an "Edit" button on each store card in `/admin/stores` → `/admin/stores/[id]/edit`, backed by a new `GET`/`PUT` `/api/admin/stores/[id]` route. The route whitelists exactly `name`, `location`, `deliveryFee`, `commissionRate` (validated: commission 0–100, delivery fee ≥ 0) — deliberately does not accept `storeCode`, `passwordHash`, `stripeAccountId`, or `role` through this endpoint, unlike the blind `Object.assign` pattern used elsewhere. Store cards also now show the commission rate, not just delivery fee. Other fields (email, phone) aren't tracked on the `Store` model at all yet — deferred until actually needed.

- **Store owners can now view their real Stripe payout status/history**: added `POST /api/store-owner/payouts`, which calls `stripe.accounts.createLoginLink()` for the store's connected Express account and redirects them straight into Stripe's own hosted Express dashboard — real payout history, per-payout status (pending/in_transit/paid/failed), arrival dates, and their linked bank account, all live from Stripe rather than duplicated in our own UI. Wired into the store-owner dashboard: once payouts are active, both the "Set Up Payouts" quick action and the payout-balance card button switch to "View My Payouts" and open the link. Also fixed the sidebar's "Payouts" nav item — it was a pre-existing greyed-out "coming soon" placeholder that only showed a toast; it now calls the same endpoint and opens Stripe like the dashboard buttons do.
